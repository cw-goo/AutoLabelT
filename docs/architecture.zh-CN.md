# AutoLabelT 架构与实施方案

## 产品工作流

默认入口为 AutoLabelT 集成工作台。主界面包含标注画布、文件列表、图片模型面板和右侧视频数据集操作，右侧提供独立训练中心的入口。标注内核来源与许可证见 `THIRD_PARTY_NOTICES.md` 和 `LICENSE`。视频采样和筛选规则以 `databuild.py` 为基线。

## 当前模块

- `autolabelt/core.py`：Qt 无关的参数、视频采样、质量筛选、YOLO 写入和逐帧元数据；`databuild.py` 规则由回归测试保护。
- `autolabelt/models/registry.py`：视频推理支持的模型 ID、任务、来源、许可与固定版本。
- `autolabelt/models/downloader.py`：后台下载可取消、权重 SHA256、本地 manifest；YOLO-World 管理专用 CLIP 文本编码器。
- `autolabelt/models/adapters.py`：本地 YOLO、YOLO-World、Grounding DINO、Florence-2 统一归一化 BBox 与提示词类别 ID。
- `autolabelt/models/worker.py`：模型下载、可选依赖安装、加载和测试推理的 Qt 工作线程。
- `autolabelt/workbench/`：标注内核及图片模型面板。
- `autolabelt/desktop.py`、`video_dock.py`：集成入口、视频停靠面板、后台任务和参数对话框。
- `autolabelt/annotation_bridge.py`：调用原项目转换器，进行 YOLO TXT ↔ 原生 JSON 复核衔接。
- 旧的独立界面和简化画布已删除；当前统一使用集成工作台。
- `autolabelt/annotations.py`、`validate.py`：YOLO 标签读写和校验。
- `autolabelt/workbench/views/labeling/label_mapping.py`：导入、数据集校验和复核共用的有序类别表读取器；统一处理 BOM、显式编号、空名称与重复类别。
- `autolabelt/workbench/views/labeling/annotation_io.py`：同目录临时文件、原子保存、文件访问预检和可回滚的批量替换。
- `autolabelt/model_square.py`：复用图片自动标注目录的厂商/模型选择对话框；保留原生目录，明确标出视频兼容性，补充视频后端专用型号。模型选择本身不触发下载。

## 安全和数据约束

PyTorch/CUDA 单独安装，模型中心不会未经确认自动升级核心依赖。Florence-2 官方模型需要固定 revision 的自定义代码，默认拒绝，必须由用户勾选确认。下载完成只表示文件到位，加载和空白帧测试推理后才标记 ready。测试推理不能证明语义准确率；Florence-2 逐框分数目前不可靠。模型版本、来源、许可、下载状态与 SHA256 保存在 manifest。下载失败不写 ready manifest。

标准数据集仍是 `images/`、`labels/`、`classes.txt`；任务参数和来源写在 `configs/`、`metadata/`，不污染 YOLO TXT。提示词顺序决定类别 ID，现有输出目录类别映射不一致时拒绝运行。输出不覆盖既有同名样本。

运行配置采用原子写入，每次运行生成独立 `run_id` 和配置快照；拒绝类别冲突、已有同前缀样本后才更新当前配置。每个样本的逐框分数单独持久化，复核转换补回原生 JSON 的 `score`；Florence-2 的不可靠占位分数存为 null。逐帧转换已验证新 JSON，构建结束不再重复全量读取复核文件。

视频面板统一检查所有任务的运行状态，禁止构建、模型操作、复核准备及同步交叉执行，并锁定项目输入。窗口关闭使用 Qt 定时器等待后台结束，避免主线程 wait；模型加载和单次推理仍采用协作式取消。同步在暂存和提交前检查取消，未提交内容由标注事务回滚。依赖安装轮询子进程状态并从独立日志句柄读取输出，取消不依赖新日志。

### 标注数据的替换与失败恢复

YOLO 导入先转换全部匹配文件到同目录的临时文件，再统一替换。任何文件出现权限、格式或类别错误，以及用户取消时，原标注保持不变；提交中途失败时恢复已替换文件。负数和超出类别表范围的 ID 均明确报错，包含文件名和行号，不能依赖 Python 负索引或自动扩充类别。

图片批量推理在运行前预检图片可读性、输出文件可读写性和目录写入能力。勾选“清除旧 JSON”后，先把所选标注移到同目录备份，推理结果写入暂存文件；成功后提交，普通异常或取消时恢复原标注。有效的零检测结果可以生成空标注，推理异常、没有返回结果和未定义的本地模型类别不能当成零检测结果保存。复核同步使用同一个批量替换机制。

手动保存和转换保存均先序列化，再写入唯一临时文件、关闭句柄并原子替换。程序不自动提升权限或修改用户数据集的 ACL；拒绝访问、文件占用和磁盘空间不足应显示具体文件及处理建议。正常失败会清理临时文件；如果系统阻止回滚，原始 `.autolabel_*.backup` 备份必须保留并在错误消息中显示位置。进程被强制结束或系统断电不属于内存事务的自动恢复范围，遗留备份不应被当作标注加载或自动删除。

更换图片目录会重置类别面板和标签编辑历史，并读取新数据集的 `classes.txt`（如果存在）。替换式导入使用新类别表，合并式导入保留已有类别；界面类别顺序不能用来替代 YOLO 的显式类别映射。模型广场确认选择才更新视频模型，关闭或取消不改变当前模型；本地权重也只有在文件验证成功后才更新配置。

## 后续优先级

1. Linux 桌面/CUDA 和真实视频端到端验收；完善多编码器定位、可选转码。
2. 模型进程隔离、严格外部哈希/签名校验、Hugging Face 大文件下载粒度进度与即时取消。
3. 同图 IoU 风险、近重复图像分析、风险原因/状态和排序；重复度与标签错误风险分开显示。
4. 局部清晰度、断点恢复、训练集拆分与更大规模性能优化。
